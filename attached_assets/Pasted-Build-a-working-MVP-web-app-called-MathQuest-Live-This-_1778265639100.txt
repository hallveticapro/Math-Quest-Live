Build a working MVP web app called MathQuest Live.

This is a classroom-safe AI-powered math adventure game for 4th grade students. The app should generate a fresh short adventure each time, but the student should only interact through preset choices and math answers. No student freeform story input.

The core idea:
A student chooses a hero setup, then plays an 8-turn adventure. Each turn:
1. The AI narrates a short scene.
2. The AI provides exactly 3 safe action choices.
3. The student chooses one action.
4. The app generates a math problem based on selected difficulty.
5. The student must answer correctly to continue.
6. After 8 successful turns, the AI generates a short ending.

The app should be portable and not tied to legacy hosted platform-specific deployment. Build it as a normal Vite frontend + Node/Express backend that can later be Dockerized and deployed on an Unraid server behind NGINX Proxy Manager.

Use this stack:
- Frontend: Vite + vanilla JavaScript
- Backend: Node.js + Express
- AI provider: OpenAI API from the backend only
- Styling: regular CSS or Tailwind if configured properly, but do not rely on Canva or external app builders
- No database
- No login
- No persistent saved student data
- No student accounts
- No retained game history after page refresh

Important security requirement:
The OpenAI API key must never be exposed in frontend code.
Use an environment variable on the server:
OPENAI_API_KEY

Create a .env.example file with:
OPENAI_API_KEY=your_api_key_here
PORT=3000

Do not commit or hardcode a real API key.

Game flow:
1. When the adventure starts, call the backend to generate the intro scene.
2. Display scene and 3 choices.
3. When the student picks a choice, hide/disable the choices and show a math problem.
4. Student answers the math problem by clicking one of four multiple-choice answer buttons.
5. If correct:
   - increment turn count and mathSolved
   - call backend for next scene using the selected choice, story summary, hero info, and turn number
6. If incorrect:
   - show friendly feedback
   - allow another attempt
7. After two incorrect attempts:
   - show a short hint
   - generate or reveal a simpler recovery problem
   - once recovery problem is solved, allow story to continue
8. After 8 successful turns, call backend for an ending scene and show the Ending screen.

No database.

MATH ENGINE REQUIREMENTS

The math should be generated by the app, not by AI.
Create a frontend mathEngine.js or shared math generator.

Each math problem should have:
- prompt
- 4 answer choices
- correct answer
- difficulty
- optional skill label

Use deterministic code to calculate the correct answer.

Difficulty guidelines:

Easy:
- addition within 1,000
- subtraction within 1,000
- basic multiplication facts 0–12
- simple place value
Examples:
“What is 347 + 128?”
“What is 9 × 6?”
“What is the value of the 7 in 4,732?”

Medium:
- multi-digit multiplication by one digit
- division facts and simple remainders
- area/perimeter of rectangles
- equivalent fractions
Examples:
“What is 34 × 6?”
“A rectangle is 8 units long and 5 units wide. What is its area?”
“Which fraction is equivalent to 2/4?”

Hard:
- multi-step word problems
- larger multiplication
- division with remainders
- fraction comparison
- angle and geometry basics
Examples:
“A bridge has 7 sections with 24 stones each. 18 stones crack. How many good stones remain?”
“Which is greater: 3/4 or 5/8?”

Extreme:
- multi-step problems
- mixed operations
- harder fraction/decimal reasoning
- more challenging geometry
Examples:
“A machine has 6 gears. Each gear has 28 teeth. If 37 teeth are damaged, how many working teeth remain?”
“A trail is 3.6 miles long. The hero walks 1.25 miles, then 0.8 miles. How much is left?”

Keep problems appropriate for strong 4th grade math.
Avoid algebra beyond simple missing-factor style problems.
Avoid decimals in Easy.
Avoid negative numbers.

Multiple-choice answers:
- Always include the correct answer.
- Generate three plausible wrong answers.
- Shuffle choices.
- Do not allow duplicate choices.

AI STORY REQUIREMENTS

The AI should only generate:
- scene title
- short story text
- exactly 3 action choices
- updated story summary
- ending title/text when ending

The AI should never generate or solve math problems.

Use the backend for all AI calls.

Use OpenAI’s API from server/openaiClient.js.
Use a modern efficient model suitable for short structured story generation.
If unsure, use a configurable model constant in server/openaiClient.js, such as:
const STORY_MODEL = process.env.OPENAI_MODEL || "gpt-4.1-mini";

If the exact API syntax is uncertain, write the code cleanly and document where the OpenAI API call happens.

Use structured JSON output.
The backend should return JSON to the frontend in this format for a story turn:

{
  "sceneTitle": "The Gear of Thunder",
  "storyText": "Nova adjusted the glowing gear as clouds swirled around the Sky Temple...",
  "choices": [
    { "id": "A", "label": "Inspect the glowing gear mechanism" },
    { "id": "B", "label": "Ask the storm sprite what it needs" },
    { "id": "C", "label": "Search the balcony for another path" }
  ],
  "storySummary": "Nova entered the Sky Temple and discovered a broken weather engine connected to a nervous storm sprite.",
  "safetyRating": "kid_safe"
}

For ending:

{
  "endingTitle": "The Inventor Who Calmed the Sky",
  "endingText": "With one final clever adjustment, Nova balanced the temple engine...",
  "badge": "Storm Solver",
  "safetyRating": "kid_safe"
}

BACKEND SAFETY REQUIREMENTS

The game must be classroom-safe for 4th grade students, ages 9–11.

The AI prompt must include strict safety rules:
- no gore
- no graphic violence
- no death
- no romance
- no profanity
- no horror
- no realistic weapons harming people
- no bullying
- no stereotypes
- no real-world politics
- no real-world religion
- no drugs, alcohol, smoking, or vaping
- no sexual content
- no self-harm
- no asking students for personal information
- no references to real student data
- no freeform instructions for real-world risky actions

Allowed adventure danger:
- cartoon adventure danger
- puzzles
- magical obstacles
- friendly monsters
- storms
- locked doors
- unstable machines
- mysteries
- dramatic but non-graphic peril

The story should resolve problems through:
- math
- observation
- kindness
- creativity
- teamwork
- courage
- patience
- problem-solving

Ancestry/species must only affect appearance and fantasy flavor.
It must never imply intelligence, morality, behavior, personality, bravery, or ability.
Gender/pronouns must only affect pronoun use.

The AI should write in a fun, adventurous, middle-grade tone.
Think classroom-safe fantasy/sci-fi adventure.
Keep each story scene short: around 100–180 words.
Choices should be short and clear.
Each choice should be safe and classroom-appropriate.

The backend should validate AI output before sending it to the frontend:
- Must have sceneTitle
- Must have storyText
- Must have exactly 3 choices
- Each choice must have id A/B/C
- Each choice label must be under 90 characters
- storyText must not be too long
- safetyRating must equal "kid_safe"

If AI output is invalid or unsafe:
Return a safe fallback scene instead of failing.

Fallback scene:
{
  "sceneTitle": "The Puzzle Path",
  "storyText": "The path ahead glows with gentle puzzle magic. Your hero studies the symbols and notices three safe ways forward.",
  "choices": [
    { "id": "A", "label": "Study the symbols carefully" },
    { "id": "B", "label": "Ask a friendly guide for help" },
    { "id": "C", "label": "Look for a hidden pattern" }
  ],
  "storySummary": "The hero is following a safe puzzle path and solving challenges.",
  "safetyRating": "kid_safe"
}

Fallback ending:
{
  "endingTitle": "The Puzzle Champion",
  "endingText": "With focus, courage, and careful thinking, your hero solves the final challenge and brings the adventure to a joyful end.",
  "badge": "Puzzle Champion",
  "safetyRating": "kid_safe"
}

Add a simple custom safety filter in server/safety.js.
It should check for obvious banned words/topics and reject unsafe output.
It does not need to be perfect, but it should provide an extra layer.

Optional:
If possible, include OpenAI moderation checking in a clearly separated function, but do not make the whole app fail if moderation is unavailable. If moderation fails, use the fallback scene.
